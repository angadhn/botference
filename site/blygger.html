Blygger is an open protocol for small blogs that quote each other by reference. Discuss, the botference browser extension, now reads Blygger posts and publishes to them. It was built during the Blygger hackathon, 20–27 November 2026.

Highlight and discuss

Highlight a passage on any web page or blyg. Write a comment on it, or chat about the page. Mention @claude, @codex or @all to ask the agents. They answer in the same thread, in a drawer at the side of the page.

On a Blygger post, the extension checks the post's own documents first. Each highlight then records the post and its version. The extension also tells you when a highlight is not word for word in the post.

A blyg's home feed shows many posts on one page. A highlight there belongs to a post only after the companion fetches that post and finds the passage in it. The companion is the small local server that the extension talks to.

Agent passages, in a marked box

Type /tk-claude or /tk-codex and an instruction in your own comment. The agent writes that passage, and the drawer shows it in a box marked as an AI's text. You can ask again, edit it, accept it, or remove it. An edited or accepted passage stays in its box when you publish. The instruction itself is not published.

Each passage comes from a separate one-shot run with no tools: claude -p, or a locked-down codex exec in an operating-system sandbox on macOS. The agent gets the page and your comment as data, and nothing else.

Publish a thread as a blyg post

Press the paper plane on your thread to publish it to your own site as a short blyg post. The post holds your words and the passage you highlighted. On a Blygger post, the passage is a quote by reference, and the post is a response to that post by default. Your site's publisher then sends the mentions, so the other blog learns of the response.

  • One-click publishing. With confirm: never, the press is the publish. The post stops for your look in two cases only: a comment that was in it would be left out, or its note was changed outside the plugin.
  • A publish queue. Every press is accepted at once. Posts go out one at a time, in the order you pressed them, up to 20 waiting. A notice tells you when each one is live.
  • New versions. Publish the same thread again and the post gets a new version, with the same id and address.
  • Copy for Blygger Studio. If you write in Blygger Studio, copy the thread as Studio's own markdown and paste it there.

The plugin writes the note into your site's notes folder. Then it runs your site's own commands, which check, build and push the post. The example set-up is a Jekyll site; see docs/blygger.md.

Agent passages in drafts written in Obsidian

A site can use the same agents in drafts that you write in Obsidian. The command botference fill-gap fills one gap and returns the text as JSON. On the example Jekyll site, a note with agents: on in its front matter opts in, and scripts/blyg-fill asks for each /tk line. The script keeps the answers in a separate file beside the note. It never writes the note.

What it runs on

The agents run on your normal Claude or ChatGPT subscription, through the claude and codex command-line tools on your own computer. You can use an API key instead.

The companion can also run on another computer of yours. You reach it through a Cloudflare tunnel, and it asks you to log in first: with a password, or through Cloudflare Access. Only the owner can publish, queue, cancel or resume a post.

What it promises

The plugin publishes in your name, so its promises matter. The laws page lists, in one sentence each, what the plugin promises when it publishes a blyg, where each promise comes from, and how it is checked today. The laws are proposed, not yet adopted.

Start here: ./botference discuss, then load frontends/plugin/extension as an unpacked extension. The README has the full set-up.
